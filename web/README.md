# CAT WARS web

Static frontend for the CatWars game and the MEOW launch token on Sepolia. Vite 7, React 19,
TypeScript 5.9, wagmi 2 and viem 2. The production export is committed at the repository root
under `dist/` and works from any static host, IPFS gateway subpath or ENS name (relative base,
one page, no server rewrites).

Validation evidence for this frontend is in [docs/FRONTEND-VALIDATION.md](../docs/FRONTEND-VALIDATION.md).
The implemented design is documented in [web/DESIGN.md](DESIGN.md) (the frontend stage's write
scope excludes the repository root, so `DESIGN.md` lives here).

## Configuration: one source of truth

The app keeps no address, chain id, ABI or RPC table of its own. At startup `src/main.tsx` calls
`loadConfig()` from `src/config.ts`, which fetches `./imd-deployment.json` next to `index.html` and
the ABI files it names (`abi/CatWars.json`, `abi/LaunchToken.json`). That manifest provides:

| Field | Used for |
|---|---|
| `chainId`, `network.name`, `network.rpcUrls`, `network.explorer`, `network.nativeCurrency` | the wagmi chain definition, public read transports (fallback over every listed URL) and explorer links |
| `contracts[]` (`CatWars`, `LaunchToken`) | contract addresses and the ABI paths loaded at runtime |
| `poolKey` | the exact Uniswap v4 pool key used for quotes and swaps |
| `network.uniswapV4` (`quoter`, `universalRouter`, `permit2`, `stateView`, …) | every quote, approval and swap call |
| `walletAddChain` | the exact `wallet_addEthereumChain` parameters offered when `wallet_switchEthereumChain` fails with 4902 |

`dist/imd-deployment.json` is generated by `scripts/manifest.mjs` from the deployment handoff
(`.imd/reads/deployment.json`) and the vetted chain table (`.imd/reads/network.json`). The script
copies each ABI from `docs/abi/<Contract>.json`, verifies its canonical keccak hash against the
handoff, and lists every other exported file with its SHA-256. Paths to those inputs can be
overridden with `IMD_DEPLOYMENT` and `IMD_NETWORK` when rebuilding elsewhere.

There are no private credentials in the bundle. The RPC URLs are the public ones from the chain
table; signing always happens in the visitor's wallet.

### Optional: WalletConnect

Injected wallets (MetaMask, Rabby and any EIP-6963 provider) work with no configuration. A
WalletConnect option (QR code and mobile wallets) is added only when a public WalletConnect Cloud
project id is supplied at build time:

```sh
VITE_WALLETCONNECT_PROJECT_ID=<your project id> npm run build
```

`vite.config.ts` inlines that value as the `__WALLETCONNECT_PROJECT_ID__` constant read by
`src/config.ts`. A build without it statically drops the WalletConnect connector and its modal
chunks, so the committed export (built without an id, since none was supplied) offers injected
wallets only and tells a visitor without one that this build has no WalletConnect option. With an
id, the export grows to about 2 MiB and 90 files, still inside the manifest limits.

## Install, develop, preview

```sh
cd web
npm ci                 # exact versions from package-lock.json
npm run dev            # Vite dev server; note the manifest is only present in dist/, so run
                       # `npm run manifest` once after a build if the dev page cannot load it
npm run preview        # serves the committed dist/ export
```

For a plain static preview from the repository root, any file server works, for example
`python3 -m http.server --directory dist 8080`.

## Rebuild the export and manifest

```sh
cd web
npm run build          # typecheck, Vite production build into ../dist, then scripts/manifest.mjs
```

`npm run build` always ends by regenerating `dist/imd-deployment.json`; run `npm run manifest`
alone after any manual change to files in `dist/`. Commit `dist/` together with the source and the
lockfile. `node_modules/` and Vite caches are ignored by `web/.gitignore`.

## Validate

```sh
cd web
npm run typecheck      # tsc --noEmit
npm test               # vitest: payout math, round decoding, eligibility, seed encoding, swap calldata
npm run build
```

Browser and interaction checks (Playwright walk with a mock wallet, the design probe) and their
results are recorded in [docs/FRONTEND-VALIDATION.md](../docs/FRONTEND-VALIDATION.md), including
the live-chain behaviour that could not be exercised.

## Layout of this directory

```
web/
  index.html            title, description, Open Graph tags, favicon; loads the verbatim engine scripts
  public/               favicon.svg, og.png, vendor/engine.js and vendor/catart.js (copied as-is)
  scripts/manifest.mjs  emits dist/imd-deployment.json after the build
  src/config.ts         manifest loader, wagmi config, minimal Uniswap v4 / Permit2 / ERC-20 ABIs
  src/hooks.ts          contract reads, transaction runner, network switch with add-chain fallback
  src/lib/              game math, engine bridge, swap calldata, formatting, error text
  src/components/       Header, Arena, Claims, History, Swap, OwnerPanel, Overlays, common
  src/styles.css        design tokens and all styling (see DESIGN.md)
  test/                 vitest suites
```
